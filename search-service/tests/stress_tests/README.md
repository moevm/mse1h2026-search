# Стресс-тестирование поискового сервиса

Скрипты для проведения стресс-тестирования API поиска.

## Подготовка к запуску

Для запуска тестов вам потребуются установленные Docker и Docker Compose. Все действия выполняются строго из директории со скриптами стресс-теста (`stress_tests`).

**Создайте папку для отчетов.** В ней будут сохраняться результаты (HTML-файлы):
   ```bash
   mkdir reports
   ```
**Создайте словарь запросов (не обязательно).** Создайте файл `search_terms.txt` в текущей директории и добавьте в него список терминов для тестирования (каждое слово или фраза с новой строки). Генератор будет использовать их для создания уникальных запросов.

## Запуск

Все параметры конфигурации передаются в виде переменных окружения перед командой запуска. Папка `reports/` должна существовать в каталоге. Пример команды запуска:

```bash
USERS=150 SPAWN=30 TIME=3m MIN_WAIT=1.0 MAX_WAIT=1.0 REPORT_FILE="stress_report.html" docker compose -f docker-compose.stress.yml up --scale locust-worker=2
```

## Переменные окружения
- `USERS` — пиковое количество пользователей.
- `SPAWN` — скорость добавления пользователей в секунду.
- `TIME` — длительность теста.
- `REPORT_FILE` — имя HTML-отчета в папке reports/.
- `MIN_WAIT` / `MAX_WAIT` — диапазон паузы между запросами одного пользователя.
- `HOST` — базовый URL тестируемого сервиса.
- `API_ENDPOINT` — путь к эндпоинту поиска (по умолчанию: /api/search).
- `LOCUST_RUN_SYNC` — true для старта задачи полной синхронизации БД перед тестом.
- `INDEXER_TOKEN` — токен авторизации для запуска синхронизации.
