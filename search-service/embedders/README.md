# Сравнение реализаций эмбеддеров в проекте

В этой папке представлены три альтернативные реализации микросервиса генерации эмбеддингов. Все они предоставляют одинаковый REST API (совместимый с Meilisearch `/embed/meilisearch`) и могут заменяться "на лету" с помощью конфигурации в `.env` бэкенда.

_Важно:_ после теста большого количества моделей можно сделать вывод, что у каждой модели свои особенности, может не так назваться выходной вектор из-за чего fastembed или sentence-transformers просто не смогут работать с этой моделью. Также было замечено, что модели с выходным вектором ~768 проходят очень долгую индексацию x3-x4 по сравнению с 384 размерностью. sentence-transformers через pytorch позволяет запустить много моделей (практические любые), однако скорость индексации уменьшается где-то на 50%, задержка инференса возрастает в 4 раза (по сравнению с onnx или встроенным в meiliserach candle)

Поэтому желательно подбирать сначала модель -> и под неё искать эффективный инференс, pytorch слишком медленный для процессора поэтому это либо ONNX/candle.
Очень часто проблемы возникают в том, как называется выходной вектор с результатами (именно переменная) т.к. это зачастую захардожено или где-то onxx файл разбит на 2.
Не везде это можно исправить написав костыль -> решение использовать другой инференс.

Также endcoding/endcoding в json может занимать время, на 22.05.2026 если использовать Pydantic, то он имеет ядро написанное на Rust, за счет чего FastAPI может напрямую кодировать в байты без промежуточных этапов (поэтому orjson и т.д. не нужны), но сейчас использование этого не проверено.

## 1. Regular Embedder (PyTorch + SentenceTransformers)

- **Путь:** `./embedders/embedder` (при `INFERENCE_BACKEND=torch`)
- **Технологии:** PyTorch + `sentence-transformers`

_Важно:_ на момент 23.05.2026 в зависимостях укзана версия sentence-transformers поддерживающая onnx, но это очень не гибкая вещь, поддерживает не все модели.

### Плюсы

- **Простота и универсальность:** Самый популярный стандарт в экосистеме Python. Работает «из коробки» с любой моделью на HuggingFace без предварительного экспорта или конвертации.

### Минусы

- **Потребление ресурсов:** Тяжелый стек. Образ Docker получается большим из-за зависимости от PyTorch.
- **Производительность на CPU:** Самая медленная скорость инференса на CPU среди всех трех вариантов.
- **Долгий запуск:** Импорт PyTorch и инициализация занимают значительное время при холодном старте.

---

## 2. ONNX Embedder (ONNX Runtime via Optimum)

- **Путь:** `./embedders/onnx_embedder` (или `./embedders/embedder` при `INFERENCE_BACKEND=onnx`)
- **Технологии:** ONNX Runtime + `sentence-transformers` (через Optimum)

### Плюсы

- **Высокая скорость на CPU:** Использование ONNX Runtime дает кратный прирост скорости инференса на CPU по сравнению со стандартным PyTorch.
- **Знакомый интерфейс:** Сохраняется привычная библиотека `sentence-transformers` (модели инициализируются тем же классом, сохраняются все методы кодирования).
- **Оптимизация:** Возможность использовать квантованные модели (например, `model_quantized.onnx`), что экономит память и ускоряет вычисления.

---

## 3. Fast Embedder (FastEmbed + ONNX Runtime)

- **Путь:** `./embedders/fast_embedder`
- **Технологии:** `fastembed` (от Qdrant) + ONNX Runtime

### Плюсы

- **Суперлегкий вес (No-Torch):** Библиотека `fastembed` не зависит от PyTorch. Размер Docker-образа и виртуального окружения получается в разы меньше.
- **Минимальное потребление памяти (RAM):** Очень низкий оверхед по памяти.
- **Молниеносный старт:** Практически мгновенный холодный запуск контейнера.
- **Встроенный параллелизм:** Оптимизирован специально для задач поиска и индексации (эффективное распараллеливание батчей на CPU «из коробки»).

### Минусы

- **Ограниченность моделей:** Для использования кастомной модели (которой нет в стандартном списке Qdrant) требуется вручную описывать метаданные (`TextEmbedding.add_custom_model`) с указанием размерностей и путей.
- **Сложность кастомизации:** Труднее переопределять внутренние этапы токенизации или логики пулинга, если они отличаются от стандартного подхода библиотеки `fastembed`.
